# Редактирование и снятие резервов ФБО

Операции доступны исключительно для строк `product_reserves` с
`delivery_type = 'ФБО'` и `shipped = 0`. Резерв блокируется `FOR UPDATE`,
проверки и изменения выполняются в одной транзакции PostgreSQL.
Новых таблиц и изменений триггеров не требуется. Уведомления 1С не отправляются.

## Редактирование

`PATCH /api/shipment_of_goods/fbo_reserves/{reserve_id}`

Передаются только изменяемые поля, например:

```json
{
  "ordered": 12,
  "account": "Вектор",
  "wb_warehouse": "Коледино"
}
```

Разрешены `product_id`, `warehouse_id`, `ordered`, `account`, `supply_id`,
`wb_warehouse`, `reserve_date`, `expires_at`.
Неуказанные поля сохраняются. Для nullable-полей допустим явный `null`.
`product_id`, `warehouse_id`, `ordered` не могут быть `null`.
Количество неотрицательное, поддерживает дробные значения как столбец numeric.
`expires_at` передаётся с часовым поясом, например `2026-11-01T12:00:00+03:00`.

Запрещены `shipped`, `delivery_type`, `is_hanging`, `is_fulfilled`, `id`,
`created_at`, `source_reserve_id` и любые неизвестные поля. Пустой PATCH запрещён.
Товар и склад нельзя менять у строк с `source_reserve_id` или дочерними резервами.
Остальные разрешённые поля таких строк доступны для изменения.

Успех: HTTP 200, `ShipmentOfGoodsResponse`, обновлённая строка в `data[0]`.

## Снятие резерва

`DELETE /api/shipment_of_goods/fbo_reserves/{reserve_id}`

Удаляет строку и её складское движение `reservation`. Существующие триггеры
пересчитывают зарезервированное количество. Физический остаток не меняется.
У дочернего резерва количество НЕ возвращается исходному резерву:
удаление означает снятие, а не отмену перемещения.
Строку, у которой есть дочерние резервы, удалить нельзя.

Успех: HTTP 204 без тела.

## Проверки и ошибки

Для обеих операций запрещены связанные `shipment_of_goods` и движения
`inventory_transactions` с типом, отличным от `reservation`.
Ожидается ровно одно складское движение резерва; отсутствие или дубли — конфликт,
требующий проверки данных. Это защищает от каскадного удаления отгрузок/движений.

- 404: строка отсутствует.
- 409: не ФБО, shipped не равен нулю, запрещённые связи или некорректная связь движения.
- 422: неправильный запрос, несуществующий товар/склад или нарушение CHECK.

Триггер `handle_product_reserve()` синхронизирует количество и исполнение,
но не товар/склад/аккаунт/тип доставки. PATCH дополнительно обновляет существующее
движение `reservation`, сохраняя его id. Триггер `update_physical_balances()`
пересчитывает новую пару товар/склад; зарезервированное количество старой пары
при смене товара/склада пересчитывается явно в той же транзакции.

## Проверка

Обычные проверки: `PYTHONPATH=. .venv/bin/python -m pytest -q tests/test_fbo_reserves.py`.

Проверки рабочей БД включаются явно:
`PYTHONPATH=. RUN_FBO_DB_TESTS=1 .venv/bin/python -m pytest -q tests/test_fbo_reserves.py`.
Все создаваемые строки используют `product_id = 'testwild'`. Изменения резервов,
движений и остатков откатываются в `finally`; значения sequence могут увеличиться.
